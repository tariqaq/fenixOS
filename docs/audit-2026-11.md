# Code audit, November 2026 (P55)

User request (2026-11-02, overnight run): "go thru all files literally everything and audit for bugs
and what not, excl security related stuff". Every source file was read whole, area by area, after
v0.1.26. Each finding has a status: **fixed** (with the commit's step), **kept** (not a bug, or not
worth the change, with the reason) or **open** (needs the user or hardware).

Security findings were out of scope and not looked for.

The fixes shipped in v0.1.27 (2026-11-02).

## Board (`board/components/fenix_*`, `board/main`, `board/sim`)

| # | File | Finding | Status |
|---|---|---|---|
| B1 | `fenix_apps/settings_ui.cpp` | The firmware update screen froze after its first phase change and never closed. All update screens shared one timer: a rebuild makes the new screen before it deletes the old one, and the old screen's delete event freed the timer and the new screen's bar and label. A pop slides the old screen out with its timer still running, so a leftover could pop a second time. Seen in the simulator as "after `ota idle` the update screen stays on top" (P50-M). Fix: one timer per screen, given to its delete event; only the newest screen's timer acts, and only while the update screen is on top. The simulator posted an OTA event on every phase change, while `ota.cpp` posts one only when an update starts or fails; `sim_sys.cpp` now does the same. New shot `update_closed` (the screen closes itself on idle; 42 goldens) | fixed (P55 step 1) |
| B2 | `fenix_sys/include/fenix_sys.h` | The header comment listed old services and tasks; a comment about the log card sat above the wrong function | fixed (P55 step 1) |
| B3 | `fenix_apps/app_pkg.cpp` | The `close_app()` comment described the time before app screens were freed by their delete event | fixed (P55 step 1) |
| B4 | `fenix_apps/led.cpp`, `shell.cpp` | `led_busy` and `led_error` were never called, so the status light never showed the dim blue and dim red that `docs/PLAN.md` §3 promised. Now `tick()` sets them from the firmware update phase (blue while one runs, red after one failed until it is dismissed); app installs do not light it. PLAN corrected | fixed (P55 step 1) |
| B5 | `fenix_ui/ui_core.cpp` | `backlight_config` faded the backlight up even while the burn-in guard rested (panel asleep). Not reachable today (only touch-driven settings and the restore sheet call it, and a touch ends the rest), so a guard only | fixed (P55 step 1) |
| B6 | `fenix_apps/shell.h`, `docs/board-info.md` (P46) | Said USB streams at 460800 baud; the link runs at 921600 (`fnx::BAUD`), 460800 is the flash speed | fixed (P55 step 1) |
| B7 | `board/sim/sim.h` | Named the script verb `ota failed <version>`; it is `ota failed_version <version>`, and phases take a version too | fixed (P55 step 1) |
| - | `home.cpp`, `session.cpp`, `stream_ui.cpp`, `widgets.cpp`, `cjk.cpp`, `fenix_pkg`, `fenix_proto`, the rest of `board/sim` | Read; no bug found. `fenix_proto` bodies are checked against `proto/vectors.txt` by its test | kept |

## Crates (`crates/`)

| # | File | Finding | Status |
|---|---|---|---|
| C1 | `fenix-font/src/lib.rs` | `plan()` could make more than 16 ranges (a `--chars` subset of scattered characters); the board reads at most 16 a size (`MAX_RANGES` in `cjk.cpp`) and skips a size with more, so that size had no glyphs. Now the ranges with the smallest gaps are joined until 16 remain (`pub const MAX_RANGES`); test in `ranges_split_at_big_gaps`; `docs/fonts.md` says so | fixed (P55 step 2) |
| C2 | `fenix-link/src/lib.rs` `StreamCanvas` | A `STREAM_RECT` with `x + w` past 65535 overflowed the u16 bounds check (a panic in a debug build); the first chunk reserved `total` bytes from the wire up front (up to 4 GB). Now u32 sums and a 256 KB cap on the reservation | fixed (P55 step 2) |
| C3 | `fenix-cli/src/main.rs` `ts()` | Log timestamps add a fixed UTC+8 (the user's zone, MYT) instead of the PC's zone. A developer tool; no time zone crate for one line | kept |
| - | `fenix-proto`, `fenix-pkg`, `fenix-sdk`, `fenix-flash`, the rest of `fenix-link` and `fenix-cli` | Read; no bug found | kept |
